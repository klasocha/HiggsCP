# HiggsCP Analysis (ρρ case)

Here is a Quick Start guide for running the whole ML flow by running some of the commands
step by step. The whole project is designed to be open source and configurable, so
you are supposed to have the needed libraries installed in order to run the code, 
make some new changes and experiment on your own.

## 🛠️ Installation 

**Requirements**: Python 3.11, Git (tested on version 2.38.0)

The most forward way to install all the dependencies is to create a virtual environment
and then install all the libraries mentioned in `requirements.txt`. Check the full installation
guide in `documentation.pdf`, *Configuring The Environment* (you can also find out how to prepare 
the working environment if you are dealing with Ares clusters provided by the PLGrid as a part of
the Cyfronet infrastructure).

## ⚙️ Data Preparation 

You can download and then preprocess original (raw) data sets by running the command below:
```shell
$ python main.py --action "download_and_prepare_original" --input "data_original"
```
This will download the data sets generated by using Monte Carlo simulation 
methods and then parse and group the kinematic vectors together with weights
belonged to the appropriate hypotheses. All the files will be in this case available in 
`data_original/`.

Alternatively, you can also download those data sets that are available on the authors' server
and already contain the set of parsed kinematic vectors and weights. If such data sets have been
prepared and are still available, run the following command to prepare the data:
```shell
$ python main.py --action "download_and_preprocess" --input "data" --features "Variant-All" --num_classes "11"
```

Please, notice that the above examples invoke the preprocessing step for the given
number of classes defining the discretisation level. In that case, we chose `11`. 
You can also experiment by trying an arbitraty odd number of classes in range `[3; )`.
See details in `documentation.pdf`

## 🧬 Model Training

To train the model you should specify its configuration, level of discretisation
stated as the number of classes, the number of epochs and input/output paths. Let's look
at the example below:

```shell
$ python main.py --action "train" --input "data" --num_classes "11" --epochs "3" --training_method "soft_weights" --weights_output "to_be_continued"
```

This command will load the data sets stored in `data/` and then run the training process over
3 epochs. The results will be stored in `results/soft_weights/to_be_continued/`. The output path,
of course, corresponds to the model configuration we chose.

If you want to restore the model state, weights and internal variables in order to continue
training, you can run the program again as shown below:

```shell
$ python main.py --action "continue_training" --use_checkpoint --input "data" --num_classes "11" --epochs 2 --training_method "soft_weights" --weights_input "to_be_continued" --weights_output "continued_from_checkpoint" 
```

There is also another way of restoring the model state, though without the state of its optimizer,
by running the similar command but without the `--use_checkpoint` option, which leads to making
the model load the serialised instance from the appropriate `model.keras` file:

```shell
$ python main.py --action "continue_training" --input "data" --num_classes "11" --epochs "2" --training_method "soft_weights" --weights_input "to_be_continued" --weights_output "continued_from_full_model"
```

Results of the two above commands execution will be saved in `results/soft_weights/continued_from_checkpoint/`
and `results/soft_weights/continued_from_full_model/`.

## 🌀 Making Predictions
If you have already trained the model, you can make predictions on validation
and training sets, as long as you are going to experiment with the model architecture
(find out more in `documentation.pdf`, *Model Architecture*):

```shell
$ python main.py --action "predict" --training_method "soft_weights" --weights_input "continued_from_full_model" --input "data" --num_classes "11" --use_checkpoint    
```

Feel free to take a look at the module reponsible for running the inference to
adapt the code to your input data set.
